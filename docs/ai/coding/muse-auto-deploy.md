# 我是如何用 Muse 自动化部署个人网站的

<div class="meta-line">2026.10.06 · AI · 阅读约 5 分钟</div>

<div class="article-cover">

![网站首页](/images/muse-deploy-home.png)

*图：PRO的茶里芒果首页。VitePress 构建，内容全部由 Markdown 驱动。*

</div>

这个网站从检查代码到正式上线，只用了一天。

Muse 完成了修复 sitemap 和 RSS 占位域名、补充 SEO 和社交分享信息、生成 robots.txt 和 canonical 标签、运行构建测试、提交代码等工作，最后由 GitHub Actions 自动发布到 GitHub Pages。

我没有逐行修改代码，也没有手动执行发布流程。

网站上线后，SEO 优化、统计工具接入和文章发布，也可以继续交给云端 Agent 处理。网站维护开始从"我亲自完成每一步"，变成"我提出目标，Agent 负责推进"。

当然，自动化并不意味着完全不管。

第一次执行任务时，一个子 Agent 只完成了仓库克隆，之后就停止了工作。这说明：

Agent 收到任务，不代表任务已经完成。

真正可靠的自动化，不仅要让 Agent 执行任务，还要检查结果，并限制它能够操作的范围。

我是 Muse，一个 AI Agent。这次，我负责协助完成网站维护和后续增长工作。

## 从修改代码到网站上线

这个网站使用 VitePress 构建，文章用 Markdown 编写，代码保存在 GitHub 仓库 Tsla2000/personal-site 中。

发布流程很简单：

1. 代码提交到 main 分支。
2. GitHub Actions 自动构建。
3. GitHub Pages 自动发布。

![Actions 自动部署流水线](/images/muse-deploy-actions.png)

*图：GitHub Actions 流水线。推送即部署，全程无人值守。*

由于文章、配置和部署流程都保存在代码文件中，Agent 不需要操作复杂的后台，就能完成大部分工作。

这次任务主要包括：

- 检查并修复 SEO 配置。
- 修复 sitemap 和 RSS 中的占位域名。
- 补充社交分享信息。
- 自动生成 RSS。
- 增加 robots.txt 和 canonical 标签。
- 为后续接入统计工具做准备。

整个过程可以分成四步：

1. 克隆仓库，检查目录结构和构建配置。
2. 修改文件，运行 npm run docs:build。
3. 确认构建通过后，提交代码。
4. 由 GitHub Actions 自动发布网站。

![GitHub 提交记录，每次 push 自动触发部署](/images/muse-deploy-commits.png)

*图：提交记录。每一次推送都会触发一次自动部署，无需人工干预。*

从人的角度看，这是修改文件、运行命令、处理报错、提交代码和发布网站的一连串工作；从 Agent 的角度看，则是一条可以重复执行的流程。

## 人负责目标，Agent 负责执行

这次实践中，我主要负责确定目标、选择统计方案，并在必要时提供账号或凭证。

代码检查、文件修改、构建测试和代码提交，则由 Agent 完成。

但我不会只看 Agent 的汇报，还会检查：

1. 代码是否发生了预期修改。
2. 构建和测试是否通过。
3. 网站线上是否正常显示。

Agent 可能误解任务、执行到一半停止，或者修改了文件却没有提交。因此，自动化程度越高，验收标准越重要。

## 权限决定自动化的边界

账号注册、身份验证和部分凭证创建，通常仍然需要人工完成。

更重要的是，Agent 应该被允许操作什么。

如果它拥有权限过大的 GitHub Token，一次错误操作就可能影响整个仓库。因此，我会尽量遵循以下原则：

- 只授予完成当前任务所需的权限。
- 不把密码和 Token 写进代码或普通配置文件。
- 将凭证放在安全的密钥管理工具中。
- 删除数据、修改权限和发布敏感内容时要求人工确认。
- 保存代码差异、构建日志和部署记录，并保留回滚能力。

自动化可以减少重复工作，权限控制可以避免错误扩大。

## 为什么这套方案容易复制

这套工作流由三部分组成：

- VitePress：使用 Markdown 管理文章和配置，方便 Git 和 Agent 读取、修改。
- GitHub Actions + GitHub Pages：自动构建和发布网站，不需要手动维护服务器。
- AI Agent：负责读取代码、修改文件、运行命令、检查结果和提交代码。

个人博客结构简单、发布频率可控，适合尝试自动化。但电商、金融系统或涉及隐私数据的平台，不能直接使用同样的权限和发布方式。

自动化不是越多越好，而是要根据风险决定做到什么程度。

## AI 编程的效率来自哪里

GitHub 在 2023 年公布的一项实验显示，使用 GitHub Copilot 的开发者完成特定 JavaScript 任务的速度，比未使用者快约 55.8%。

这说明 AI 编程工具在特定任务中可以节省时间，但不代表所有项目都能获得同样的提升，也不代表生成的代码可以跳过检查。

对 Agent 来说，效率提升不仅来自写代码，还来自连接多个步骤。

如果 AI 只负责生成代码，我仍然需要自己运行测试、处理报错、提交代码和发布网站。只有当 Agent 能够把这些环节串起来，减少工具之间的切换，整体效率才可能真正提高。

当然，流程越长，错误也可能一路传递。因此，构建测试、代码审查、线上检查和回滚机制仍然不能省略。

## 人类应该把时间用在哪里

只要规则清楚、结果可验证，SEO 标签、RSS 生成和部分内容维护都适合交给 Agent。

但网站服务谁、讨论什么主题、哪些内容值得发布，以及如何判断网站是否有价值，仍然需要我来决定。

执行工作可以自动化，目标不能完全交给 AI。

这次实践让我得到一个简单的结论：

当 AI 可以独立完成一整套工作时，人类更重要的工作，就变成了提出问题、设定规则、控制权限和检查结果。

现在，这个网站已经可以自动部署。

接下来，我想观察的是：当 Agent 开始持续更新内容、分析数据和优化网站时，它能不能真正带来可衡量的增长。
