# 如果你想让 Muse 自动优化个人网站的 SEO

<div class="meta-line">2026.10.13 · AI · 阅读约 10 分钟</div>

最实用的方式不是让它一次性"帮网站做 SEO"，而是让它先检查整个网站，再按问题清单逐项修改，最后验证修改有没有生效。

以你的 VitePress 个人网站为例，可以把这件事拆成三部分：技术 SEO、文章 SEO、持续监控。前两部分可以让 Muse 直接分析和修改代码，第三部分则需要结合搜索引擎提供的数据，不能只凭 AI 判断。

![SEO 三部分：技术 SEO、文章 SEO、持续监控](/images/muse-seo-three-parts.webp)

## 一、先让 Muse 检查哪些地方？

### 1. 技术 SEO：让搜索引擎能找到网页

检查页面标题、描述、规范网址（Canonical）、站点地图 `sitemap.xml`、`robots.txt`、404 页面、重复 URL、页面加载速度，以及构建后的 HTML 是否包含正文。VitePress 原生支持站点元数据配置，也支持生成站点地图。

### 2. 文章 SEO：让内容更容易被搜索到

扫描所有 Markdown 文章，找出标题太宽泛、缺少摘要、主题重复、缺少内部链接、图片没有替代文本等问题。Muse 可以给出修改建议，并直接修改 Frontmatter 和文章内容，但不能为了关键词而篡改原意。

### 3. 持续监控：根据真实搜索数据迭代

接入 Google Search Console，观察网页是否被收录、哪些搜索词带来曝光、哪些页面有曝光却很少被点击。再让 Muse 根据数据提出修改方案。

## 二、可以直接交给 Muse 的任务提示词

下面这段可以直接复制到 Muse，让它先审计你的网站代码，再实施优化。

---

请为当前 VitePress 个人网站实施一套可持续维护的 SEO 优化方案。

不要只给建议，请先检查现有项目代码、目录结构、VitePress 版本、部署配置和所有文章，再制定方案并实际修改。

**一、先做全面审计**

检查以下项目：

1. 全站 title、meta description 是否存在、准确且具有页面唯一性。
2. 页面 URL、Canonical 标签、Open Graph 和社交平台分享元信息是否正确。
3. 是否正确生成 sitemap.xml，是否需要配置 robots.txt。
4. 是否存在 noindex、错误的 canonical、失效链接、404 页面或重复内容。
5. 生产构建生成的 HTML 是否包含对应页面的标题、摘要和正文。
6. 页面图片是否有合理的 alt 文本，图片尺寸和加载方式是否合理。
7. 文章之间是否缺少必要的内部链接，导航结构是否便于用户和搜索引擎发现内容。
8. 页面性能、移动端体验和无障碍语义是否存在明显问题。
9. 检查首页、文章页、分类页、标签页和留言板等页面，分别判断哪些应该被搜索引擎收录。不要默认所有页面都应该收录。
10. 检查项目现有的 SEO 配置，避免重复添加 meta 标签、插件和依赖。

先输出审计报告，按 P0（影响收录或存在严重错误）、P1（重要优化）、P2（一般改进）分类，列出问题、证据、修改方案和验收标准。

**二、实施技术 SEO**

审计完成后直接修改代码：

- 配置合理的全站默认 title 和 description，并为每篇文章生成或补齐独立的标题与摘要。
- 正确配置 sitemap.xml，使用真实的生产域名，排除不应收录的页面。
- 检查并修复 canonical、robots、Open Graph 等元信息。
- 优先使用 VitePress 原生能力，只有确实需要时才增加依赖。
- 优化图片 alt、内部链接、页面语义结构及明显的性能问题。
- 不要将留言板、管理页面、测试页面等不适合搜索的内容盲目纳入索引。
- 不要随意修改已有 URL；如果确实需要修改，先说明影响并提供重定向方案。
- 不要删除、重写或大幅改动原有文章内容。

**三、实施文章 SEO**

扫描所有 Markdown 文章，识别：

- 标题与正文主题不匹配；
- description 缺失或重复；
- 多篇文章主题重复；
- 内部链接不足；
- 图片缺少 alt；
- 标题层级不合理；
- 文章之间缺少必要的关联和推荐。

为每篇文章生成优化建议。只自动修改明确的技术问题，以及不改变原意的元数据问题。涉及标题重写、文章重组、关键词策略和正文修改时，先输出建议，不要擅自改写。

不要堆砌关键词，不要生成虚假的作者经历、数据、引用或案例，不要为了 SEO 添加没有实际价值的内容。

**四、自动化检查**

尽可能增加可重复执行的 SEO 检查脚本，并接入现有构建流程。检查项目至少包括：

- 缺失或重复的 title、description；
- 缺失或格式错误的 canonical；
- sitemap 中的 URL 是否符合预期；
- 失效的站内链接；
- 意外出现的 noindex；
- 生产构建是否成功。

如果某项检查无法可靠自动化，请明确说明原因，不要伪造检查结果。

![SEO 自动化检查流程](/images/muse-seo-automation.webp)

**五、验证和交付**

完成后：

1. 运行项目现有的构建、测试和 SEO 检查。
2. 检查构建产物中的实际 HTML，而不是只看源代码。
3. 核对 sitemap、robots.txt、canonical 和 meta 标签。
4. 汇总修改的文件、修改原因、检查结果及仍需人工处理的问题。
5. 给出 Google Search Console 的接入步骤，以及后续如何依据真实搜索数据持续优化。

请先阅读项目现状，再决定实现方式。所有修改必须符合当前 VitePress 版本，不要套用未经验证的旧配置。未经授权，不要直接推送代码、修改生产环境密钥或执行不可逆操作。

## 三、如何让它以后自动优化，而不是只做一次？

我建议把 SEO 做成一个小型的持续维护流程，而不是每次都临时向 Muse 提问。

**文章提交或更新时**：检查标题、摘要、内部链接、图片 alt 和 Frontmatter；发现问题就提示。

**每次部署前**：运行构建与 SEO 检查。严重问题阻止发布，一般问题生成报告。

**每周或每两周**：读取 Search Console 数据，找出曝光高但点击率低、已收录但表现不佳、长期未被收录的页面，生成优化清单。

这里需要区分两个概念：Muse 可以通过代码和脚本自动检查、修改、构建；但要判断搜索表现是否真的提升，需要搜索引擎数据。它也不能保证文章被收录或排名上升。

参考资料：VitePress 的 [站点配置文档](https://vitepress.dev/reference/site-config)、[站点地图生成文档](https://vitepress.dev/guide/sitemap-generation)，以及 Google Search Console 的 [官方入口](https://search.google.com/search-console/about)。

我的建议是先完成一次全站审计，再做自动化。否则，Muse 很可能只是批量补上描述、关键词等标签，看起来做了很多事，却没有解决真正影响收录的问题。
