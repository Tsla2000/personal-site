# AI 数据分析工作流：从原始数据到可复核的决策建议

让 AI 总结一份表格并不难，难的是确保结论真的来自数据、计算可以复现，而且没有把相关性说成因果关系。数据分析技能应该帮助用户把原始数据变成可检查的证据和决策建议，而不是生成一份看起来专业的报告。

这套流程适用于 CSV、Excel、产品行为数据和运营报表。涉及敏感数据时，先确认数据授权和处理环境，不要把个人信息或商业机密随意上传到第三方模型。

## 1. 先检查数据质量

开始分析前，记录数据来源、时间范围、字段含义、行数、重复记录、缺失值、异常值和单位。检查日期格式、时区、金额单位以及唯一键，避免把数据问题误判为业务变化。

如果字段定义不清，先提出问题，不要自动猜测“转化”“活跃用户”或“收入”的口径。

## 2. 先定义问题和指标

将业务问题拆成可以计算的指标，并明确分母、分子、时间窗口和过滤条件。例如，“转化率下降”必须说明是哪个步骤、哪个用户群体、哪段时间，以及采用什么分母。

先写分析计划，再计算，能减少在结果出来后不断挑选有利指标的风险。

## 3. 用确定性工具计算

优先使用 SQL、Python、表格公式或其他可复现工具计算计数、比例、分组和时间序列。让模型协助编写代码、解释异常和整理结论，但不要把模型的心算当成数据事实。

对于重要数字，保留计算逻辑、输入范围和必要的中间结果，方便复核。

## 4. 区分事实、解释与建议

报告最好分成三层：

- **观察事实：** 数据直接显示了什么。
- **可能解释：** 哪些机制可能导致变化，还有什么替代解释。
- **行动建议：** 建议采取什么行动，预期观察什么指标。

如果没有实验或足够证据，不要把时间上的先后关系直接写成因果关系。样本量不足、口径变化或数据缺失都应成为结论的限制条件。

## 5. 输出可复核的交付物

建议交付数据清洗说明、指标口径、计算脚本或查询、核心表格、结论摘要、限制条件和下一步验证方案。图表应该服务于具体问题，而不是为了让报告看起来丰富。

## 如何评估分析质量？

关键数字能否由原始数据和计算过程复现？不同时间段是否采用相同口径？结论是否承认不确定性？建议是否能通过后续指标验证？如果这些问题没有答案，报告即使语言流畅，也还不能支持重要决策。
