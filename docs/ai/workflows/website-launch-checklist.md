# 网站上线检查清单：部署前验证功能、SEO、移动端与回滚

网站构建成功，只能说明构建工具没有发现阻断错误，不代表线上体验没有问题。链接可能指向错误路径，移动端布局可能溢出，分享卡可能没有更新，搜索引擎也可能读到错误的 canonical 地址。

下面的清单适合静态网站、文档站、个人博客和小型产品官网。每次发布前按项目风险取舍，不必把它变成没有重点的仪式。

## 1. 功能与链接

- 首页、主要分类、详情页和 404 页面都能正常打开。
- 站内链接没有 404、错误语言版本或意外跳到旧域名。
- 复制、下载、表单、搜索和主要按钮都实际操作过。
- 下载文件存在，内容与页面描述一致。
- 如果使用中英文版本，语言切换和对应页面都正确。

## 2. 移动端与可访问性

- 在窄屏下检查标题、卡片、表格、导航和代码块。
- 页面没有横向溢出，关键按钮有足够的点击区域。
- 图片有合理的替代文本，表单控件有可读标签。
- 仅用键盘也能完成主要操作，焦点状态清晰。
- 图片按需加载，避免首屏被大文件拖慢。

## 3. SEO 与分享

- 每个重要页面都有独立的 title 和 description。
- canonical 指向正式域名上的当前页面，而不是预览域名或旧站。
- sitemap.xml 包含应被收录的页面，robots.txt 指向正确的 sitemap。
- 中英文页面有正确的 hreflang，且不是只做逐字翻译。
- Open Graph / Twitter Card 标题、描述和图片正确。
- 结构化数据能解析，页面内容与结构化数据一致。
- 预览环境和内部工具页没有意外开放索引。

## 4. 数据与隐私

- 页面浏览统计在允许的情况下正常工作。
- 复制、下载等关键事件能被记录，且事件名稳定、可读。
- 不把用户输入、剪贴板内容、文件内容或 API 密钥发送给分析服务。
- 如果统计被广告拦截器屏蔽，页面功能仍然正常。
- 明确哪些事件用于产品分析，避免收集与决策无关的数据。

## 5. 部署与回滚

- 在目标环境运行正式构建和 SEO 检查。
- 核对构建环境变量：正式域名、base 路径和 canonical。
- 检查部署后的实际 URL，而不只看 CI 绿色状态。
- 保留上一个可用版本；确认如何回滚或重新部署。
- 记录本次变更、已执行检查、未执行检查和已知风险。

## 建议的验收顺序

先运行构建与自动化检查，再抽查高流量页面和关键用户路径，最后确认正式域名、分享卡和统计事件。自动化适合覆盖重复检查，人工检查则用于判断实际体验和风险。

如果希望把发布前检查交给 Agent 重复执行，可以使用[网站上线验收技能](../../skills/website-launch-check)，并参考[AI 项目交付流程](./ai-project-delivery-workflow)规范最终交接。
