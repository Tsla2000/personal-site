# 浏览器自动化流程

目标是稳定完成用户授权的网页操作，而不是尽可能多地点击。所有操作都必须围绕用户目标，避免绕过权限、验证码、访问限制或网站安全机制。

## 1. 先勘察
确认网站、登录状态、目标记录、输入来源、完成条件，以及哪些操作会产生外部影响。先观察页面结构和可用控件，区分稳定选择器、可访问性标签、文本定位与易变的坐标定位。

## 2. 拆解成状态机
把流程写成明确步骤：进入页面 → 等待目标状态 → 读取当前值 → 执行动作 → 验证结果 → 记录结果。每步定义成功条件、超时处理与失败恢复。避免仅依赖固定 sleep 或“点击后假定成功”。

## 3. 安全边界
- 发送消息、发布内容、提交订单、删除数据、修改权限等有外部影响的动作，执行前先向用户确认，除非用户已明确授权该具体动作。
- 不读取、展示或保存与任务无关的私人数据、Cookie、令牌或密码。
- 不尝试绕过 CAPTCHA、付费墙、访问控制或反自动化措施。
- 对批量操作先用少量样本试跑，确认结果后再扩大范围。

## 4. 可靠性设计
- 优先使用语义定位与可访问性信息，避免脆弱的绝对 XPath 和屏幕坐标。
- 每次提交后重新读取页面状态，确认成功提示、目标记录或状态变化。
- 仅对幂等操作自动重试；可能重复付款、重复发送或重复创建时，先检查是否已成功。
- 处理空状态、加载状态、错误提示、会话过期和网络失败。
- 记录操作时间、目标、结果和失败原因，不记录敏感字段。

## 5. 交付与维护
交付流程图或步骤表、输入输出约定、权限需求、失败恢复方式和人工介入点。页面结构变化时先重新勘察，不要盲目反复点击。若工具不支持某项操作，明确说明限制，不假装已执行。

## 验收清单
- [ ] 用户目标与授权范围明确
- [ ] 每一步都有可观察的成功条件
- [ ] 高风险动作有确认机制
- [ ] 失败可停止或恢复，不会无限重试
- [ ] 有真实结果证据与失败记录
- [ ] 未收集或输出无关的敏感数据
