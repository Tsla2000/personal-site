# 内容一稿多用

目标是提高一份原创素材的复用效率，而不是把同一篇稿子复制粘贴到不同平台。始终以用户提供的原始材料为事实边界，不补造引用、数据、经历或来源。

## 1. 先识别素材
读取全文并记录：核心论点、证据、案例、关键数字、可引用原句、作者立场、不能公开的信息。若材料不完整，明确缺口，不用常识补成事实。

## 2. 建立母稿
先用 3–5 句话写清：
- 这份内容要回答什么问题？
- 最值得传播的一个结论是什么？
- 哪些证据支撑结论？
- 哪些反例、限制或不确定性必须保留？
- 读者看完后应理解或采取什么行动？

## 3. 按平台重组
根据用户指定平台制作对应版本：
- **公众号 / 长文**：完整论证、背景、证据、反方观点与结论。
- **X / 短帖**：一个清晰观点，配一个可验证理由；长线程按逻辑递进，不拆成空洞金句。
- **短视频口播**：开头交代问题，中段用具体例子解释，结尾回到结论；避免夸张承诺。
- **邮件 / 社群**：突出读者为什么现在需要知道，以及下一步是什么。
- **官网 / SEO 页面**：标题贴合真实搜索意图，先回答问题，再补定义、步骤、FAQ。
不要为了平台风格篡改原意；必要时删减，不可伪造语气或立场。

## 4. 口吻与事实检查
保留作者常用词和句式，避免模板化开头、过度总结、重复结论和无来源的“研究表明”。所有数字、书名、人名、日期、引语逐项回查原文。引用外部资料时单独标明来源，不将推断写成事实。

## 5. 输出交付
默认交付：
1. 一份母稿摘要；
2. 各平台可直接编辑的版本；
3. 每个版本的目标读者、传播切口与字数；
4. 需要作者确认的事实或敏感点。
若用户只要某个平台，直接交付该版本，不额外堆一整套内容。

## 不要做什么
- 不要把同一段文字机械地改短、改长就当作多平台适配。
- 不要添加用户未提供的个人经历、产品承诺或业绩。
- 不要为了“爆款”夸大标题，制造虚假冲突。
- 不要把内部业务、私人信息或未发布材料放进公开稿。
