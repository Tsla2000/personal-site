# 出海变现转化

适用：新词/出海站已见流量（或即将上登录与支付），需要把会话变成注册、生成、付费，并留住用户、降低支付风险。

本流程提炼自 @JiangK82705（蒋云何）公开复盘《副业出海小白 首日破百刀，5天破千刀的新词经验分享》，改写成 Agent 可执行步骤；工具与 URL 见 `references/tools.md`。不捏造原文未写数据；案例数字仅作「曾发生过什么」的参考，不是你的承诺指标。

找词与 D0–D5 上站节奏见技能「出海新词上站」。

## 0. 开工前确认

1. **当前阶段**：仅落地页 / 已有登录 / 已有支付 / 已有退款与风控问题。  
2. **变现形态**：订阅、积分包、或两者（原文先推促销月订 + 高价积分锚定，后补低价积分包）。  
3. **支付与分析**：Stripe（含 Radar）、GA4、后台订单表是否已打通。  
4. **行为观测**：Clarity / Plausible（或同类）/ Crisp 是否已接。

## 1. 假生成效果（无登录也能提停留）

竞品若「只有页、无登录支付」，但点生成有加载动画/假结果：

1. 首页提供可点的生成入口与加载反馈（假生成即可）。  
2. 目的：拉长停留、模拟真实产品感，利于 SEO/GEO 阶段观察。  
3. 有流量且准备变现后，再换成真模型与真积分扣减。

小白路径：页面结构、文案、FAQ、定价套餐都可先模仿竞品，再按数据改。

## 2. 定价：锚定 + 促销订阅 → 再补「只玩一次」

可按阶段组合（按调用方品类改价位，勿照搬金额为唯一真理）：

1. **锚定**：一次性积分包标较高起步价，衬托订阅「更便宜」。  
2. **主推**：限时促销月订（倒计时、折扣文案）；让对比下订阅显得划算。  
3. **后补低价积分包**：梗热度退潮或用户明显「只想玩一次」时，上更低价积分包，并把付费墙默认侧重积分包。  
4. **年付大单单独记账**：不可算成稳定 MRR；见第 7 节 EFW。

竞争变多后，用户往往更偏一次性付费——用数据决定默认推订阅还是积分包。

## 3. 套餐文案价值主张

1. 功能跑通后，套餐/积分可**先照抄一个竞品站**，再迭代。  
2. 若后台出现「创建了订单但无人付款」：优先改**套餐文案**是否讲清价值（权益、次数、与竞品差异），而不是先怪支付通道。  
3. 改文案后继续盯：订单创建率、付款成功率、套餐选择分布。

## 4. 选模型与供应商

1. 功能优先调通，再纠结最优成本。  
2. 用 **Artificial Analysis**（https://artificialanalysis.ai/）按**成本与分数**选模型。  
3. 通宵赶工时可用 Codex 等设 goal 持续跑优化，但仍以「可付费闭环」为验收。

## 5. 留存放大：上线时就要想，不要生成完就结束

产品不要停在「生成一次 → 结束」。上线规划里至少预留：

| 能力 | 作用 |
|---|---|
| **Feed** | 可刷他人作品，延长停留、给下一次生成灵感 |
| **分享** | 用户把结果带出去，带来自然扩散 |
| **「Put me in it」类入口** | 看到别人成品想把自己放进去 → 再进生成 |

在信息架构与首版 roadmap 里写明上述入口；红利期过后流量腰斩时，没有留存/分享会加倍痛。

## 6. 埋点与支付同步上

上支付**同一天**对齐分析事件，避免事后只能翻数据库：

1. **GA4** 事件与后台一致：至少 `sign_up`、购买/订阅成功；核对 GA4 计数 ≈ 后台注册/成功付款笔数。  
2. 记录并复盘**失败付款**（拒付、Radar 拦截、同一用户重复尝试）。  
3. 转化漏斗建议分来源看：如 chatgpt.com、自然搜索、direct、导航站——导航站流量转化常偏低，优化时优先高质量来源（chatgpt.com / 自然搜索）。

关键产品动作：让用户**真正跑通一次生成**；生成过的用户付费意愿通常远高于只注册未用的用户（原文复盘强调这一点）。

## 7. Stripe Radar / EFW

1. **尽早开启 Stripe Radar** 相关规则，降低欺诈成交后再退款的概率。  
2. 收到 **EFW（早期欺诈预警）**：对相关大单（尤年付）**主动退款**，降低争议与账号风险。  
3. 年付/大额单单独监控，不并入「已锁定经常性收入」叙事。

## 8. 行为数据三件套

用户不一定留言，行为会说话：

| 工具 | 看什么 | 怎么用 |
|---|---|---|
| **Microsoft Clarity** | 录屏、卡点 | 找到表单/付费墙/生成流程卡死处 |
| **Plausible**（或同类轻量统计） | 来源与趋势 | 配合 GA4 看 chatgpt.com / Google 等 |
| **Crisp** | 客服入口 | 让用户能直接找到你，反馈改产品 |

示例闭环：有订单没付款 → 改套餐文案；流量下滑且一次性需求多 → 补低价积分包。

## 9. 流量质量优先级

1. 重点看 **chatgpt.com** 与 **Google 自然搜索** 的注册→付费。  
2. **导航站**（如 toolify、taaft 等）带来的注册转化常接近 0——可作曝光，勿当主转化池，也不要为此过度改产品。  
3. 热度退潮时：先用 Trends / GSC / 会话数据区分「搜的人少了」还是「排名掉了」，再决定 SEO 抢救 vs 产品留存。

## 10. 执行清单（可打勾）

- [ ] 无登录阶段也有假生成/加载反馈  
- [ ] 定价有锚定；促销订阅与积分包策略写清；必要时已补低价包  
- [ ] 套餐文案讲清价值；有单无付时已改过文案  
- [ ] Feed / 分享 / 「把我放进去」类入口在 roadmap 里  
- [ ] GA4 `sign_up`与购买事件与后台对齐抽查  
- [ ] 失败付款与 Radar 拦截有记录  
- [ ] Stripe Radar 已开；EFW 有主动退款预案  
- [ ] Clarity + 统计 + Crisp 已接，并有「本周改了什么」记录  

## 11. 不要做什么

- 不要生成完就结束，却指望梗热度永远在。  
- 不要支付上了埋点没上。  
- 不要把年付大单和 EFW 单算进稳定 MRR。  
- 不要只砸导航站外链却不改内容与留存。  
- 不要把原文案例的美元数字写成你的保证收益。

写在最后：先让用户用起来（生成一次），再让付费说得通（文案+定价），再让人愿意留下并分享。
