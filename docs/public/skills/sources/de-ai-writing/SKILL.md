# 去AI味写作

这是一份可安装的技能正文。把它放到助手的 `workflows/de-ai-writing/SKILL.md`（或 `ai/SKILL.md`）。用户把全文粘贴进 Cursor 或 Grok Bot 时，按下面的规则执行，不要把它收成一段简介。

## 何时使用

- 公众号长文、投资简报、X / 社媒文案需要按用户本人的口吻重写或润色。
- 成稿已经写完，用户只要去掉机器味，不要重写论点。
- 用户说「去AI味」「按我的风格写」「公众号润色」「投资简报」。

## 何时不用

只管文字语气和信息守恒。

- 封面、文章头图、推文大图：交给 `cover_image_gen`。
- 正文里的静态结构图：交给 `diagram-design`。
- 可交互的等轴测拆解：交给 `anatomy`。
- 产品界面和交互规范：交给 `ai-ui-design`。

用户同时要文字和封面时，先交文字，并说明封面要另开 `cover_image_gen`。不要在本技能里写绘图提示词。

## 硬规则

1. 永远读最新版。动手前先读当前这份 `SKILL.md`，不凭记忆里的旧摘要写作。
2. 风格档案优先。已有档案时，用词、节奏和判断方式都跟档案，不另起一套「更像人」的通用腔。
3. 最小改动，同时信息守恒。清理机器味时只改语气和句式，不增删事实、数字、时间、因果和结论。
4. 没有档案时，先建档案再写。没有样本就不要假装已经掌握用户口吻。

## 建立风格档案

向用户要至少一篇本人成稿。从样本里只提取可复用的写法，不把某篇文章里的一次性事实写进档案。记下：

- 句子长短、段落节奏、是否常用短判断句。
- 称呼读者的方式，以及第一人称出现的频率。
- 用户会写的判断，以及用户不用的套话。
- 事实和观点的出场顺序。

档案用短条目写在本次对话里。用户要求保存时，再写成技能目录旁的风格档案。建档后先给用户看条目，确认后再写正文。

## 新写

1. 确认材料里有哪些事实、数字和用户已经做出的判断。
2. 读最新版技能；有档案就用档案，没有就先建档。
3. 按档案写公众号长文、投资简报或社媒文案。
4. 不补用户没给的数据，不把不确定写成确定。
5. 交稿时给正文。若刚建了档案，把档案条目附在后面。

## 清理成稿

1. 先冻结原文里的事实、数字、引用和结论。
2. 删掉空泛升华、对称排比、元叙述和没有信息的连接词。
3. 只调整句式和语气，让它靠近风格档案；没有档案时，先从这篇成稿和用户另外提供的样本建档。
4. 保留原文的信息和顺序。只有原顺序让事实读反了，才调整顺序，并在交稿时点明动了哪一处。
5. 不附长篇写作说明。最多用两三句说明改了什么语气。

## 输出

- 成稿正文。
- 新建档案时的档案条目。
- 不输出封面、图解 HTML 或界面代码。
