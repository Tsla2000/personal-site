# AI界面设计规范

这是一份可安装的技能正文。把它放到助手的 `workflows/ai-ui-design/SKILL.md`（或 `ai-2/SKILL.md`），并带上同目录的 `references/`：至少要有 `tokens.css` 和组件参考。用户粘贴全文时，按下面的规则做界面，不要收成一段简介。

## 何时使用

- 对话框、消息流、输入框。
- 工具调用卡片、需要用户确认的工具卡。
- 预览面板、设置弹层。
- 默认技术栈是 React + Tailwind + Framer Motion。用户指定别的栈时，仍遵守令牌和交互规则，只换实现。

## 何时不用

只管界面和交互规范。

- 文案口吻：交给「去AI味写作」（`de-ai-writing`）。
- 配图和封面：交给 `cover_image_gen`。
- 概念图解：静态图用 `diagram-design`，等轴测交互解剖用 `anatomy`。

## 开工

1. 先向用户确认品牌色。没有确认之前不写组件。
2. 品牌色只写进 `tokens.css` 的令牌。从 `tokens.css` 复制令牌再进组件。
3. 组件内禁止裸 HEX。颜色、圆角、间距、字号都引用令牌或已经映射到令牌的 Tailwind 主题。
4. 读最新版技能和 `references/` 里的组件参考，再改界面。

## 必须守住的交互

- 输入法守卫：组合输入（IME）未结束时，不把 Enter 当成发送。
- 流式滚动：新 token 到来时，只有用户本来就贴在底部才跟随；用户上翻阅读时不抢滚动。
- 工具确认卡：会改数据或对外发送的工具调用，先展示参数，等用户确认再执行。只读工具可以标明「只读」，不必同一张确认卡。
- 消息流、输入框、工具卡、预览、设置是五块分开的区域。不要把设置塞进消息气泡。

## 动效

用 Framer Motion 做短过渡：消息进入、工具卡展开、设置弹层。动效不挡输入，不在流式输出的每个 token 上重播整段动画。

## 验收清单

交界面前逐项核对：

1. 品牌色来自已确认的令牌，组件里搜不到裸 HEX。
2. 中文输入法组字时按 Enter 不会发出半截拼音。
3. 流式输出时上翻不会被拽回底部。
4. 会写数据或对外发送的工具有确认卡，参数可见。
5. 预览和设置不跟消息流混在同一层滚动里。
6. 文案若要改口吻，改口令牌之外另走 `de-ai-writing`，本技能不改写作风格。

## 输出

- 使用令牌的界面代码。
- 若仓库里还没有令牌文件：一份只含已确认品牌色的 `tokens.css` 草稿，并说明它该放进 `references/`。
- 不输出封面图提示词，不输出出版级图解 HTML。
