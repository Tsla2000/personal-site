# 个人网站搭建

适用：个人站、作品集、品牌站、产品落地页。目标是「内容可维护 + UI 有辨识度」，而不是一次甩给 AI 出一整站。

本流程提炼自公开分享（《从0搭建个人网站：8大类60+UI设计必备清单》，PamelaAI·H @pamelaaaaa1218），改写成 Agent 可执行步骤；资源清单见同目录 `references/ui-catalog.md`（若已安装 `ui-design-refs` 技能，优先读那份）。

## 0. 开工前确认

向调用方确认并写进简报：

1. **你是谁 / 给谁看**：一句话定位、目标读者。
2. **站要完成什么**：展示作品、导流订阅、卖产品、招人等（可多选，标优先级）。
3. **必备页面**：首页、关于、作品/案例、文章、联系/赞助等。
4. **技术栈偏好**：未指定时默认 Vite / Next / 静态站均可，优先调用方现有仓库。
5. **品牌气质**：2–4 个形容词；有主色就记下，没有就先中性灰占位，**不要套用知名产品品牌色**。

## 1. 内容底稿（先文档，后页面）

不要直接让 AI「随便写个个人站」。先建一份内容底稿（飞书文档优先，也可用 Notion / 本地 Markdown）。

底稿至少包含：

- 个人/品牌介绍（短版 + 长版）
- 项目/案例（名称、一句话、链接、截图说明、你的角色）
- 服务/产品（若有）
- 联系方式与社媒
- 想放进站的素材清单（图、PDF、视频）

工作方式：

1. 把底稿链接或导出文件交给 AI；需要批量导出时，可用飞书 CLI 等工具拉正文与附件。
2. **改内容只改底稿**，再让 AI 同步到页面；避免散落在多个组件文件里改文案。
3. **图片落地规则（必做）**：底稿里的图不要长期以外链形式出现在生产站。导出时下载到项目 `assets/`（或图床），改成本地/自有 CDN 路径；发布前全文搜索是否还有 `feishu` / `lark` / 临时外链残留。

## 2. UI：对着好站抄结构，再交给 AI 实现

最佳路径：**找好看的站 → 让 AI 抓代码 / 截图 / 风格关键词 → 按你的内容整合**。

按需从下列品类各挑 1–3 个参考（完整清单见 `references/ui-catalog.md`）：

| 品类 | 用来干什么 |
|---|---|
| 组件库 | 按钮、表单、导航、卡片等可改源码的部件 |
| 动效 | 标题动画、滚动、光效、参数化背景 |
| Landing / Hero | 首屏与整页区块灵感 |
| 移动端 UI | 小屏布局与触控组件 |
| 交互 | 微交互、设备模型、作品展示 |
| 配色与素材 | 色板、插画、图标 |
| AI 建站 | 快速出方案/原型后再手工收 |
| 设计 Skill / 提示词 | 给编程助手装前端设计规则 |

用法约束：

1. 先定 **一个** 主参考气质，再局部借组件；不要把 10 个站的特效叠在同一页。
2. 让 AI 接入组件前，核对：**技术栈是否匹配、是否可商用、是否还在维护**。
3. 个人站若带商业性质，商用授权未标明时，让 AI 先排查再抓代码。
4. 首屏优先：一个清晰的价值主张 + 一个主 CTA；动效最多点缀 1–2 处高影响时刻。

若已安装商店中的 `frontend-design`（Anthropic）或本站 `AI界面设计规范`，做页面时一并启用：前者管「别出 AI 默认审美」，后者管聊天/Agent 产品界面细节。

## 3. 实现顺序

1. 信息架构与路由（按底稿页面列表）
2. 全局令牌：色、字号、圆角、间距（全部用变量，组件内禁止裸 HEX）
3. 首页 Hero + 导航 + 页脚
4. 作品/案例列表与详情
5. 关于与联系
6. 移动端与暗色（若需要）收尾
7. 性能：大图压缩、字体子集、减少整页入场动画

## 4. 发布检查清单

- [ ] 文案全部来自最新底稿，无占位「Lorem / 这里是介绍」
- [ ] 无飞书/临时图床外链；断链抽查通过
- [ ] 主 CTA 可点；移动端导航可用
- [ ] 标题、描述、OG 图已填（SEO）
- [ ] 投资/收益相关内容已加免责声明（若适用）

## 5. 不要做什么

- 不要跳过底稿，直接生成空洞个人站模板。
- 不要一次塞满所有动效库。
- 不要把参考站整站视觉（含品牌色与标志）原样搬进客户站。
- 不要在未确认授权时复制付费组件源码。

写在最后：先做出**第一页**（一个建站工具 + 一个参考站 + 一套配色），再迭代。
