# 数据分析与决策

目标是让数据回答一个具体决策问题。先定义口径和可验证的计算路径，再分析分布、趋势、漏斗、分群与异常，最后给出可执行的下一步。

## 1. 明确决策问题
确认分析对象、时间范围、观察单位（用户、订单、会话、事件）、核心指标、分母和期望决策。区分描述性问题（发生了什么）、诊断性问题（为什么）和决策问题（接下来做什么）。

## 2. 检查数据质量
读取字段定义与样本；检查空值、重复记录、时间范围、时区、异常值、事件延迟、用户/订单去重口径和数据来源变化。先给出质量问题及其对结论的影响，不在口径未确认时直接比较。

## 3. 建立分析路径
按问题选择方法：
- **趋势**：按天/周/月观察总量与转化率，区分季节性和结构变化。
- **漏斗**：曝光 → 点击 → 使用 → 关键行为 → 付费；每步明确事件定义、去重方式和转化率分母。
- **分群**：按新老用户、会员状态、渠道、版本或行为分层，避免总体平均掩盖差异。
- **留存**：明确 cohort、首日定义、观察窗口和右删失问题。
- **异常定位**：对比变更前后、不同版本与来源，先验证时间关联，再讨论因果。
- **实验**：检查随机分组、样本量、主要指标和护栏指标；没有可靠实验设计时，不把相关性说成因果。

## 4. 计算与可复现
优先用脚本或明确公式计算；记录过滤条件、去重逻辑、分子分母和样本量。抽样复算关键结果。图表必须服务于判断，标清时间范围、单位和口径；样本不足时直接说明。

## 5. 结论格式
每条结论包括：观察到的事实、可能解释、证据强弱、业务影响和建议动作。将“数据证明”“与……一致”“可能原因”分开表述。对不能由数据支持的原因，列出待验证假设和下一项最便宜的验证。

## 6. 决策输出
优先给出 1–3 个动作，写清目标指标、验证窗口、成功阈值、成本和停止条件。避免只有描述没有决策，也避免把建议写成确定性预测。

## 不要做什么
- 不要只报均值而不看分布与分群。
- 不要混用不同时间窗、分母或事件定义。
- 不要把相关性写成因果。
- 不要忽略未成熟 cohort、数据缺失和样本偏差。
- 不要编造数据或填补没有证据的数字。
